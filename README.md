# Nyaa Enhancer Presets

[Arad119/Nyaa-Enhancer](https://github.com/Arad119/Nyaa-Enhancer) の Chrome 向け改造版です。投稿日で絞り、シーダーが多い順に結果を見られます。元作者の公式版とは別のプロジェクトです。

`nyaa.si` と `sukebei.nyaa.si` で起動します。検索や追加読み込みは、開いているサイトのドメインを保持します。

**[ダウンロード](https://github.com/came815/nyaa-enhancer-presets/releases)** · [初めての導入](#初めて導入する場合) · [更新方法](#すでに導入済みで更新する場合) · [困ったとき](#うまく表示されない場合) · [使い方](#使い方)

## 主な機能

初期表示は日本語です。一覧上部・拡張ポップアップ・設定画面の **表示言語** で **日本語 / English** を切り替えられます。選択を保存した後、その画面を再読み込みして反映します。ほかのタブには次の再読み込み時に反映します。

ポップアップから設定を開けます。対象サイトのタブがない場合は、拡張内の設定画面が開きます。設定の保存に失敗した場合は成功表示にせず、スイッチは保存前の状態に戻します。

| プリセット | 対象期間 |
| --- | --- |
| 1日（Day） | 直近24時間 |
| 1週間（Week） | 直近7日 |
| 1か月（Month） | 直近30日・初期選択 |
| 3か月（3Month） | 直近90日 |
| 1年（Year） | 直近365日 |

カレンダー上の今月・今年ではなく、検索開始時刻から遡ります。開始時刻はURLに保持され、追加ページも同じ境界で判定します。新しい時点で検索し直すときは **更新（Refresh）** を押してください。

![期間プリセットとシーダー順のローカル検証画面](docs/images/presets-desktop.png)

公開テンプレート・CSSを用いた、自動読み込みを一時停止中のローカル検証画面です。表示内容は架空データです。[狭い画面のダーク表示](docs/images/presets-mobile-dark.png)も確認しています。

## 導入

**PC版Google Chromeで使います。初めての方は以下の手順だけで導入でき、Node.jsや開発用コマンドは不要です。** Chrome Web Storeには登録していないため、ZIPを展開して読み込みます。

### 初めて導入する場合

1. [ダウンロードページ（Releases）](https://github.com/came815/nyaa-enhancer-presets/releases)を開き、使いたい版の **Assets** を開きます。現在の配布版は **Pre-release（試用版）** です。
2. **`nyaa-enhancer-presets-バージョン番号-chrome.zip`** をダウンロードします。例：`nyaa-enhancer-presets-1.18.0-chrome.zip`。`-source.zip` や GitHubの **Source code (zip)** は開発用なので、通常の導入では選びません。
3. ダウンロードしたZIPを右クリックし、**「すべて展開」** を選びます。展開したフォルダーは、ドキュメント内など、今後も移動・削除しない場所に置いてください。
4. 展開先を開き、**`manifest.json` が見えるフォルダー** を確認します。Chromeで選ぶのはこのフォルダーです。ZIP自体や、さらに一段上のフォルダーは選びません。
5. Chromeのアドレスバーに **`chrome://extensions/`** を貼り付け、Enterを押します。
6. 右上の **「デベロッパー モード」** をオンにします。
7. **「パッケージ化されていない拡張機能を読み込む」** を押し、手順4のフォルダーを選択します。
8. 拡張機能の一覧に **Nyaa Enhancer Presets** が表示され、スイッチがオンになっていることを確認します。
9. 対象サイトの一覧ページを開きます。すでに開いている場合は **ページを再読み込み** してください。上部に期間の選択欄が表示されれば、起動を確認できます。

選ぶフォルダーの例：

```text
NyaaEnhancerPresets/  ← Chromeでこのフォルダーを選ぶ
├─ manifest.json
├─ background/
├─ content/
├─ popup/
└─ …
```

設定を開くときは、Chrome右上の **パズル型アイコン（拡張機能）→ Nyaa Enhancer Presets** を押します。ピン留めすると、次からツールバーのアイコンを直接押せます。対象サイトを開いていなくても、ポップアップから設定画面へ進めます。

### すでに導入済みで、更新する場合

**同じフォルダーを使って更新します。拡張機能をChromeから削除して入れ直す必要はありません。** 自動更新には対応していません。

1. 新しい版の **`-chrome.zip`** をダウンロードし、いったん別のフォルダーへ展開します。
2. 現在Chromeに読み込ませているフォルダーを、バックアップとして別の場所へコピーします。
3. 現在の導入フォルダーの中身を、新しい版の中身で置き換えます。**導入フォルダーの名前と場所は変えず、直下に `manifest.json` がある状態を保ってください。**
4. Chromeで **`chrome://extensions/`** を開き、デベロッパー モードをオンにします。
5. **Nyaa Enhancer Presets** のカードにある **丸い矢印（再読み込み）** を押します。表示されるバージョンが新しい番号になったことを確認します。
6. 開いている **対象サイトのページも再読み込み** します。設定画面やポップアップを開いたままの場合は、閉じて開き直してください。

ファイルの置き換えが済んでいる場合は、手順4からで大丈夫です。同じフォルダーで更新することで、拡張IDと保存設定を維持できます。

### うまく表示されない場合

| 状況 | 確認すること |
| --- | --- |
| 「マニフェストが見つからない」などのエラー | ZIPを展開し、`manifest.json` が直下にあるフォルダーを選び直す |
| 期間の選択欄が表示されない | 拡張のスイッチがオンか確認し、対象サイトの一覧ページを再読み込みする。Chromeの拡張の「詳細」でサイトへのアクセスが許可されているかも確認する |
| 更新したのに古い表示のまま | 拡張カードの丸い矢印を押した後、対象ページも再読み込みする |
| 操作欄が二重に表示される | 元のNyaa Enhancerや、別フォルダーから読み込んだ同じ拡張を無効にする |
| 拡張に「エラー」が表示される | 「エラー」を開き、表示された内容とバージョンを添えて[Issue](https://github.com/came815/nyaa-enhancer-presets/issues)で知らせる |

元の Nyaa Enhancer と同時に有効にすると、同じページに二重に作用します。元版を使っている場合は無効にしてからこの改造版を有効にしてください。元版の設定は自動移行されません。

補足は [導入ガイド](docs/INSTALL.md)、Chrome側の読み込み・再読み込み操作は [Chrome公式の手順](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked) を参照してください。Firefox 側のソースは上流のまま保存されており、この改造版のサポート対象外です。

## 使い方

1. 一覧上部の **1日 / 1週間 / 1か月 / 3か月 / 1年** を選びます。
2. プリセット選択・クイック検索 はシーダー降順で検索します。通常の並べ替えも期間条件を保ちます。
3. 末尾に近づくと続きを自動で取得します。期間選択欄はスクロール中も上部に残り、読み込み状態と件数を確認できます。
4. **自動読み込みを停止** で自動取得を止め、**自動読み込みを再開** で再開します。手動のオン・オフは保存されます。**さらに読み込む** で手動取得することもできます。
5. 通信エラーやアクセス制限、タイムアウト、10ページ連続で該当結果がない場合は自動取得を停止します。表示された理由を確認し、再開操作を行ってください。取得中は **キャンセル** でも停止できます。

自動読み込みは初期状態でオンです。末尾の約600px手前から、1.5秒以上の間隔で順番に取得します。タブが非表示の間は新しい取得を始めません。再開時は未取得の次ページから続けます。

言語切り替えは拡張機能の操作欄・設定・通知に適用します。サイト元来のメニューや投稿タイトル、説明文、ユーザー入力、外部APIからの作品データはそのまま表示します。上流版の過去の変更履歴は英語で保持します。

結果は読み込み済みの範囲だけです。検索上限や変動するシーダー数があるため、期間内の全件取得・厳密な一時点ランキングは保証しません。通信失敗・応答形式の変化・アクセス制限は、検索完了として扱わず取得を止めます。

## 一括ファイル取得

ダウンロードは `.torrent` ファイルを順番に取得します。件数が多いと、通信時間に加えてファイル間の0.5秒の待機が積み重なります。ZIPは収集完了後に作成するため、その間は保存ファイルが現れません。

進捗欄の **ダウンロードを中止** で、通信中のファイルと残りの取得を止められます。ZIPをキャンセルした場合はZIPを保存しません。個別保存で取得済みのファイルは残ります。1件の通信が20秒で終わらなければ失敗として次へ進み、同時に複数の一括取得は開始しません。

## 検証と開発

v1.18.0では既存機能の一覧更新・設定保存・クライアント送信を見直しました。追加・差し替えされた行にも選択欄とフィルターを適用し、個別機能の失敗が後続機能の処理を止めない構成にしました。変更範囲と比較基準は [既存機能の見直し](docs/REBUILD.md) を参照してください。

```text
npm ci
npm test
npx playwright install chromium
npm run test:ui
```

ブラウザテストはローカルの架空データで行います。実サイトへのブラウザアクセスが実行環境のサイト安全ポリシーで拒否されたため、実サイトでの動作確認は未実施です。検証内容は [QA記録](docs/QA.md) に記載します。

変更をコミットした後、`npm run package` で Chrome ZIP・対応ソース ZIP・SHA256一覧を `dist/` に生成します。対応ソースを Chrome ZIP と同じリリースに置いて配布します。
